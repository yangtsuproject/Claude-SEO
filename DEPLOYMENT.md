# Vercel Deployment Guide

## Backend Deployment (Vercel Serverless Functions)

### Important Note
While you CAN deploy the backend to Vercel, it's **NOT recommended** for this project because:
- BullMQ (job queue) requires a persistent server
- Background jobs won't work properly on serverless functions
- Redis connections may timeout

**Recommended alternatives for backend:**
- **Railway** (easiest): https://railway.app
- **Render**: https://render.com
- **Fly.io**: https://fly.io

### If you still want to use Vercel for backend:

1. Create new Vercel project for backend
2. Set root directory to `backend`
3. Add environment variables (see below)
4. Note: Background jobs won't work - you'll need to modify the code

## Frontend Deployment (Vercel - Recommended)

### 1. Deploy Frontend to Vercel

1. **Import Project**:
   ```bash
   # Go to https://vercel.com/new
   # Import your GitHub repository
   ```

2. **Configure Project**:
   - **Framework Preset**: Vite
   - **Root Directory**: `frontend`
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`

3. **Environment Variables**:
   Add these in Vercel dashboard (Settings → Environment Variables):

   ```
   VITE_CLERK_PUBLISHABLE_KEY=pk_live_...
   VITE_API_URL=https://your-backend-api.railway.app
   ```

### 2. Deploy Backend to Railway (Recommended)

1. **Go to Railway**: https://railway.app

2. **Create New Project**:
   - Click "New Project"
   - Select "Deploy from GitHub repo"
   - Choose your repository
   - Select `backend` as root directory

3. **Add Services**:
   - PostgreSQL database (click "Add Database" → PostgreSQL)
   - Redis (click "New" → Database → Redis)

4. **Environment Variables**:
   Railway will auto-create `DATABASE_URL` and `REDIS_URL`. Add these:

   ```
   # Clerk
   CLERK_SECRET_KEY=sk_live_...
   CLERK_WEBHOOK_SECRET=whsec_...

   # APIs
   DATAFORSEO_LOGIN=your_email@example.com
   DATAFORSEO_PASSWORD=your_password
   ANTHROPIC_API_KEY=sk-ant-...

   # Server
   PORT=3001
   NODE_ENV=production
   FRONTEND_URL=https://your-frontend.vercel.app

   # Google Sheets (optional)
   GOOGLE_SERVICE_ACCOUNT_EMAIL=...
   GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY=...
   ```

5. **Deploy**:
   - Click "Deploy"
   - Wait for build to complete
   - Copy the public URL (e.g., `https://backend-production.railway.app`)

6. **Run Database Migrations**:
   - Go to Railway project
   - Click on your service
   - Go to "Settings" → "Commands"
   - Add custom start command: `npx prisma migrate deploy && npm start`

### 3. Update Frontend Environment Variables

Go back to Vercel frontend project:
- Settings → Environment Variables
- Update `VITE_API_URL` to your Railway backend URL:
  ```
  VITE_API_URL=https://your-backend.railway.app
  ```
- Redeploy frontend

### 4. Configure Clerk Webhooks

1. Go to Clerk Dashboard: https://dashboard.clerk.com
2. Configure webhook URL:
   ```
   https://your-backend.railway.app/api/auth/webhook
   ```
3. Subscribe to events:
   - `user.created`
   - `user.updated`
   - `user.deleted`
4. Copy webhook secret and add to Railway environment variables

## Alternative: All-in-One Railway Deployment

You can deploy BOTH frontend and backend to Railway:

1. **Backend**: Follow steps above
2. **Frontend**:
   - Create new Railway service
   - Root directory: `frontend`
   - Build command: `npm run build`
   - Start command: `npm run preview`
   - Add environment variables

## Post-Deployment Steps

### 1. Test the Application
1. Visit your Vercel frontend URL
2. Sign in with Clerk
3. Create a test project
4. Try keyword research with a few keywords

### 2. Monitor Logs
- **Frontend**: Vercel Dashboard → Your Project → Deployments → View Function Logs
- **Backend**: Railway Dashboard → Your Service → View Logs

### 3. Check Database
```bash
# Install Railway CLI
npm i -g @railway/cli

# Login
railway login

# Link to project
railway link

# Open Prisma Studio
railway run npx prisma studio
```

## Troubleshooting

### "Failed to fetch" errors
- Check `VITE_API_URL` is correct
- Verify backend is running on Railway
- Check CORS settings in backend

### Database connection errors
- Verify `DATABASE_URL` is set
- Run migrations: `npx prisma migrate deploy`
- Check PostgreSQL service is running

### Redis errors
- Verify `REDIS_URL` is set
- Check Redis service is running on Railway

### Clerk authentication errors
- Verify both publishable and secret keys
- Check webhook configuration
- Ensure webhook URL is accessible
